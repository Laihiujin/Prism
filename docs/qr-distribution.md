# 扫码分发

一级入口：侧边栏「扫码分发」(`/qr-distribution`)，旧的 `/tasks/distribution` 复用同一页面。

1. 在素材管理为视频保存通用或平台预设（标题、正文、标签、封面）。
2. 创建分发：选择多条素材、目标平台、每条素材对应的平台预设、每平台接收账号数。
3. 选择「每账号领取一条」或「每账号领取整组」。前者按素材顺序分配，账号数不超过素材数；后者把整组复制给各账号。
4. 「登录成功后自动执行」默认关闭，可以跳过。后台为各平台启动独立登录会话，表格末列显示二维码；TikTok、YouTube 打开网页交互登录。
5. 任意成功登录的账号均可领取。系统根据实际平台身份入库，生成独立账号任务包，同一账号在同一分发中只领一次。
6. 查看任务包，调整本次发布数量、首条时间、间隔分钟数或每日条数。保存安排不会提交发布；立即执行或提交定时发布才会进入原有发布队列。未选中的素材保留待执行。

## 时间与执行

- 时间按北京时间解析，存储时带时区。
- 每日频率按均匀间隔换算，例如每日6条对应每4小时一条。本次发布数量限制本次提交条数，不代表无限循环发布。
- 立即开始：首条立即，后续按间隔设置发布时间；定时开始：每条时间为首条时间加条目序号乘间隔。
- 定时任务复用原有发布服务，平台定时能力及平台允许的时间范围由对应发布适配器处理。
- 已提交的条目不再参与修改或重复提交。剩余素材可以分批执行。
- 任务包记录的是「已提交队列」，实际发布成功或失败在任务管理查看。
- 提交中连接中断或服务重启，结果标记为待核对，不自动重发。

## 登录刷新与生命周期

- 后台每5秒检查登录结果，关闭页面不停止分发。
- 每30秒读取原浏览器中的二维码，适配平台自身的二维码更新；此操作不刷新页面。
- 仅等待扫码且二维码显示期已过、或平台明确返回过期时，才按冷却预算重载原页面。已扫码和人工验证期间不自动重载。
- 重载至少间隔10分钟，逐次增加到2小时；每个独立登录会话滚动24小时最多12次（首次初始化及失败尝试也计入预算）。冷却期间手动刷新也遵守限制。
- 每个平台每次领取使用独立的临时登录标识。下一个账号会开启新的隔离会话，并使用独立刷新预算，不挤占后续账号的登录名额。
- 登录服务异常进入冷却，之后可重建会话；分发默认24小时到期，API支持1至168小时。停止或到期会清理待登录窗口，已生成任务包保留。
- 分发、预设快照、领取进度、刷新预算和任务包保存在本地数据库的 `qr_distributions` 表。进程租约避免多个服务进程重复消费同一分发；其他进程修改时返回409，稍后重试。
- 浏览器进程本身不跨重启保留；任务元数据保留，恢复时按冷却预算重新登录。

## API 与 Agent

- `GET /api/v1/tasks/distribution`
- `POST /api/v1/tasks/distribution`
- `GET /api/v1/tasks/distribution/{task_id}`
- `POST /api/v1/tasks/distribution/{task_id}/action`

Agent 共用工具目录：`list_qr_distributions`、`create_qr_distribution`、`get_qr_distribution`、`qr_distribution_action`；MCP、CLI `prism tool list/invoke` 与工具目录 API 共用同一入口。

创建示例（ID和预设必须来自素材库）：

```json
{
  "name": "单平台整组派发",
  "materials": [
    {"file_id": 1, "presets": {"douyin": "PRESET_ID"}},
    {"file_id": 2, "presets": {"douyin": "PRESET_ID"}}
  ],
  "platforms": ["douyin"],
  "accounts_per_platform": 1,
  "allocation": "all_per_account",
  "auto_publish": false,
  "schedule_type": "immediate",
  "interval_seconds": 600
}
```

派发后调整并执行：

```json
{
  "action": "publish",
  "package_id": "PACKAGE_ID",
  "schedule": {
    "schedule_type": "scheduled",
    "scheduled_time": "2030-01-01T10:00:00+08:00",
    "item_count": 2,
    "interval_seconds": 1800
  }
}
```

使用 `configure` 保存相同安排，暂不执行；`refresh` 需传 `platform`；`stop` 停止接收新登录。

## IP pool 与 Persona

IP pool 是账号固定代理的管理层；代理网关提供代理入口；Persona 保留账号浏览器环境和登录状态。在系统设置选择浏览器后端，在账号管理打开账号环境，在代理管理绑定网络线路。未知身份的首次派发登录与已有账号环境分开，登录结果通过现有账号持久化流程保存。

当前实现仍使用原有 JSON 代理节点存储与账号表绑定；这次修正重复绑定、禁用节点被自动分配、解绑覆盖失效状态、换绑失败丢失旧绑定和删除已绑定节点的问题，不宣称完成代理存储的整体迁移。

远程画面支持网页点击、拖动、滚轮、文字和常用按键。操作系统文件选择框、浏览器工具栏、系统权限弹窗不在网页截图中。

# 原始素材追溯与保真

## 本地发现

1. 优先用户明确路径；核实文件存在，打开原文件。再用本机 Everything 查询产品名/型号/版本、品牌资产目录和相邻项目素材。
2. Everything 工具或 CLI 已可用时使用其真实接口；未配置时说明回退到原生文件搜索，不声称已经调用。只搜索与任务有关的目录和文件名，避免输出账号与密钥。
3. 区分正视、侧视、背面/室内部件、同系列不同型号。至少比对用户确认图与找到的原图；无法判断就阻断受影响产品画面，继续其他准备。
4. 本地 manifest 记录 asset_id、path、SHA-256、型号/版本、角色、已目视核对项。路径与文件摘要存在本地任务输出中，发布技能仓库仅保留脱敏模板。

## 四种引用

- product_original：产品结构唯一依据。每个涉及产品的生成或修订必须实际传入当前核对过的原文件。
- logo_original：字标及透明通道依据。原始矢量/透明 PNG 优先，形状与字距不能由生成模型随意替换。
- style_only：用户封面截图，只提取标题大小、视觉重量、密度、光影、场景机制；不能把其不同型号产品或代言人复制到本任务。
- prior_candidate：连续性与局部编辑依据，必须与原始产品图并行使用，不能独占产品权威。

如果提供者不能接受本地参考图，先选择真实支持的工具或按其文档上传后引用。不能偷偷退回文生图、说“有缓存就够了”，也不能伪造上传成功。上传应限本任务所需素材。

## 必检项

外轮廓、长宽比例、组件数量、镜头/传感窗口、按键行列、屏幕、接口、握把、旋钮、接缝、标识、材质与颜色。
遮挡或裁切可以符合构图，但不能靠隐藏关键区域来冒充校准通过。未公开内部机构和屏幕 UI 保持未知，不推测填补。局部放大也需要原图支持的细节；不能生成看似精密的假结构。

## 融合与复核

实际相机透视、安装方式、尺度、光向/软硬、色温、反射、环境色、接触阴影和遮挡应自洽。分装在两面的部件各在相反的一面，一个视角里只出现能看到的那一面。
不能将原图贴到不相容的风景或石台上就称其已融合。若采用合成，须有同等严格的物理融合与原图核验；原图保真不能替代融合，融合不能替代产品保真。
每次修订重新传原图并检查，记录版本。失败稿保留为失败，不继承为产品新源。

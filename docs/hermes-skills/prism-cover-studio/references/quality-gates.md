# 验收与状态

## 生成前

核对事实、产品原文件、Logo、风格来源；把每次调用实际使用的原图路径/上传标识与摘要记录。创意卡先通过平台差异检查，才开始生成。相同背景换字不能靠批量产出补救。

## 看实际图片

1. 原图对照：型号、轮廓、组件、镜头/窗口、按键、屏幕、旋钮、字标逐项核对。
2. 融合：透视/尺度、安装结构、光向/色温、材质反射、接触阴影、遮挡边界。产品不应悬浮、同侧重复安装或像从另一幅图剪贴。
3. 品牌：透明 Logo 结构/大小/位置/净空，文字准确，颜色与 VI 对齐。不能用有底板的假透明标，也不能让 Logo 压过标题。
4. 视觉：一个主焦点、清楚的主次、恰当留白、没有裁切事故、标题逐字正确。
5. 手机缩略图：分别在约160px与320px宽看完整封面，判断标题、主题和产品是否仍可辨认；不能只看放大图。
6. 横向比较：去掉文字仍应看到平台/版本的实质差异。不是给所有平台套一个风景。

任一核心产品结构、Logo、指定文案错误或严重融合失败，直接标记 failed，不计入完成数量。提供者返回成功、格式校验通过都不能推翻这一条。

## 状态

planned → generated → needs_review → approved / rejected → delivered。
本地视觉检查和用户批准分开记录；用户要求过关后扩展时，必须有明确 approved_by_user=true，且绑定文件 SHA-256。用户夸一处不等于所有平台均批准。
新生成/修改文件后旧批准失效，重新检查。相同问题两次修订仍不解决，报告证据与缺口，不继续批量付费重试。

## 工具校验

`check_delivery.py` 检查文件存在、PNG/JPEG尺寸、精确比例、源图摘要、每次生成包含产品原始引用、候选阶段/批准摘要和最终数量。它不做 OCR/感知，不证明原图实际传入提供者或画面质量过关；调用记录和目视证据仍须真实。
交付清单只写实际执行过的检查，不把读取文件说成执行了技能脚本。

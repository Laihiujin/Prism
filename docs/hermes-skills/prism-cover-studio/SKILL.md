# Prism 封面与标题工作室

统一处理封面、标题、简介、标签。先说明本次实际加载了哪些指导；读取说明不等于运行了验证，也不等于成品过关。

如果有品牌规范更好。

## 按任务读取

- 文案或多平台发布包：[标题与字段](references/title-copy.md)。
- 封面/多版本：[平台创意](references/platform-design.md) 与 [验收](references/quality-gates.md)。
- 真实产品、Logo、人物或截图：[原文件与引用](references/source-assets.md)，生成前必读。
- Prism MCP/CLI：[工具适配](references/prism-tools.md)。独立安装时可使用宿主图像工具，不要求 Prism 服务存在。

## 先立创意，再生成

提取内容事实、用户参考、目标平台、比例、数量、必用文字、已有批准和预算范围。用户已给出的信息不重复询问；普通创作授权足以推进可逆准备，发布单独按授权执行。
为每个平台写一张简短创意卡：受众观看动机、内容承诺、封面短文案、唯一主视觉、场景机制、标题结构、原图来源、与其他平台的实质区别。平台调性是编辑选择，不是算法保证。

多平台至少在场景、视觉机制、信息关系、叙事视角中有实质差异；仅换颜色、字重、位置、产品角度不算不同。用户要求两套时，第二套也要提出独立机制；横竖各自构图。用平台×版本×比例矩阵计数，不把废稿计入完成数量。
先完成代表性主稿并做实际检查，再扩展。用户要求“过关后再继续”时停在可查看的样稿等待用户决定；没有明确批准不记录为批准，也不把一张获认可扩展为所有平台都获认可。

## 产品与品牌硬要求

每次生成与修订都重新带入已核对的原始产品图，记录路径和摘要；缓存、历史成图、提示词中的型号和模型记忆不能替代原图。先搜本地原文件，Everything 可用时优先，找不到再用本机文件搜索。核对型号/版本不能只看文件名。
锁定结构、组件、字标和比例，参考生成仍需比对实际结果。产品与场景共同生成/编辑，统一透视、光向、色温、反射、遮挡、接触与安装关系。禁止用生硬原图覆盖掩盖产品错误或不融合。精确字标如需独立合成，必须保留透明边界与留白，不能引入底板或改变主视觉。

## 生成记录与最小修订

在任务输出目录保存创意卡、完整提示词和本地 manifest。每次调用列出实际输入的原图引用，明确原图/风格/Logo 的权威角色；不声称工具接收了它不支持的图片参数。
实际提供者、工具、job/path 和引用关系写入记录。先检查成品全图、原图对照、手机缩略图，再记录结论；错误定位到产品、融合、构图、文案或标识，不无条件整批重生成。相同缺陷连续两次修订仍失败时，报告具体阻断和候选，停止自动消耗额度。
用 [manifest.example.json](references/manifest.example.json) 的结构记录任务。可运行 `python scripts/check_delivery.py <manifest.json>` 检查本地文件、源图哈希、逐次引用、数量和比例；脚本不能替代视觉判断或用户批准。

## 交付状态

明确区分“方案 / 已生成待审 / 检查失败 / 用户批准 / 最终交付”。给出实际图像、平台、版本、比例、路径、检查范围及未解决问题。不把已读 skill、生成接口成功或文件数量当作质量通过；不保证点击率和爆款。
发布包包含独立的 title / description / tags / cover_copy / cover_path，视频号另列 short_title。仅请求文案时不启动图像生成，仅请求封面时不擅自发布。

## 维护与许可

Prism 内本目录是唯一源，旧 prism-title-topic 和 prism-social-content 仅保留兼容入口。参考来源、许可与固定版本见 [SOURCES.md](SOURCES.md)。产品原图、品牌字标、字体和样片不包含在代码许可内，也不随技能发布。
